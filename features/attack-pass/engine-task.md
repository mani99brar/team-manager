# Engine worker: the attack pass in the controller (PRD_ATTACK_PASS sections 3, 4, 6 items 1 to 7, Appendix A)

## Goal

A feature.json 2.5.0 feature can declare `attack`, and its run gets an attack pass at the review step: in parallel with the reviewers, one `claude --print` attacker job per angle works in its own worktree of the frozen candidate and returns findings, each with a test file that asserts a stated requirement and fails on the candidate; the controller re-runs each test on a clean copy, a read-only skeptic job judges the reproduced ones, and the controller writes `<run>/attack.json` (Appendix A), the `attack` node's events, the cost records and, when a finding is verified, one attention record. The pass is report-only: the review verdict alone decides the run, and a pass that fails, times out, is refused or finds nothing changes nothing. `attack-pass`, `attack-label` and `attack-tally` exist, export 1.8.0 carries the record, and a feature without `attack`, every older feature version and every run prepared before this change behave exactly as today.

## Design (settled)

- **Configuration.** feature.json 2.5.0 with the optional `attack` of PRD section 3 (with `requirements`, G5) in `contracts/workflow/feature.schema.json`; `attack` on 2.4.0 or earlier is refused; bounds as section 3. Policy 1.3.0 in `contracts/workflow/verification.schema.json` adds the optional `attack_check` `{argv, timeout_seconds}` with `{file}` exactly once in `argv`; a feature with `attack` whose policy has no `attack_check` is refused at launch. `attack` and the prefix `attack-` join the reserved ids. `init` keeps writing its current versions.
- **Guard ([L7] for the tests).** Launch (its dry run included) and pipeline preflight refuse a feature with `attack` while a path on the secret-file list exists: `Blocked: an attack pass needs <path> off this host: move it, then launch again`. The list is `~/.config/vps-wallet.env` plus `WORKFLOW_ATTACK_SECRET_FILES` (colon-separated), read once at prepare and pinned in `plan.attack.secret_files`. The pass checks the pinned list again before any attacker starts and records the pass `refused` (no job runs) when a listed file exists.
- **Prepare** pins `plan.attack`: the settings, the secret-file list, the angle brief paths and digests, the skeptic brief, the `attack_check` and the copies of the `requirements` documents. A plan without `attack` means no pass. Launch passes the settings to prepare as the sidecar's are passed; the dry run prints them under `attack`.
- **Placement (G7 as changed by [L4], [L9] and [L11], PRD 4.1).** Automatic runs only (the `review` node calls `automatic.review_candidate` only when `plan["automatic"]`). `review_candidate` starts the pass as one child process, `sys.executable -m workflow.attack <run>` with `cwd` the controller's own checkout ([L11]) and `start_new_session=True`, recorded in `<run>/attack.running.json` (pid, command line, started_at), before it launches the reviewers, and again on a re-entry while the pass is not terminal. The review's wait loops (`collect_print`, `wait_reviews`, `wait_grace`) are not changed. Every exit of `review_candidate` goes through one `close_or_wait_attack(runtime)`. The review counts as decided when `<run>/review.json` for this candidate exists at that exit, whether `review_candidate` returned or raised (approved, blocked, a deadline's partial record, a reviewer stop not confirmed) ([L9]): then it waits until the pass ends or passes its overall bound (PRD 4.1, Deadlines; past the bound it stops the child and records the pass `failed`) and raises the exception again afterwards; an exit with no such `review.json` stops the child and records the pass `failed` with the closing event; on `KeyboardInterrupt` and `TransientInfraError` it stops the child, records nothing, and the next controller resumes. The review verdict alone decides the run. The reviewer deadline never stops the pass and the pass never extends it. The child resumes from `attack.json`: it keeps every finished step, kills recorded orphans ([L3]), records an attacker or skeptic left `running` as `failed` (error `interrupted`) and runs only what is still owed. A child that exits without a terminal `attack.json` makes the pass `failed`. Nothing reruns an interrupted attacker.
- **Attacker job.** Worktree `<runs root>/<run id>.attack/worktree` ([L2]), outside the run directory, a detached checkout of the candidate commit made under the worktree lock; the policy `setup` runs there first. One print job per angle, the angles one after another in that worktree, reset between angles the same way ([L2], [L10]); each job's pid and session id go to `<run>/attack.jobs.json` and the child terminates its jobs' process groups on SIGTERM ([L3]). Each job is built like a print reviewer's (a sibling of `print_command`, see Building blocks; `popen_claude`, `role_flags(plan, "judges")`), tools `Read,Glob,Grep,Edit,Write,Bash` under the permission handling native workers use ([L6]; `dontAsk` cannot grant Write), deny rules on credential and wallet files, no `git push`/`git commit`, no `pkill`/`killall`, `--max-budget-usd <budget_usd>`, the verifier's scrubbed environment (`checks.check_environment`: `*_KEY`, `*_TOKEN`, `*_SECRET`, `*_PASSWORD`, `GH_*`, `GITHUB_*` dropped; only the Claude Code auth and provider variables that `sessions.scrub_env` keeps for print jobs, such as `CLAUDE_CODE_OAUTH_TOKEN`, are put back so the job can start), the C14 deny rules from `sessions.worker_settings`, cwd the attack worktree and `--add-dir` for that worktree only. Its prompt is the angle brief, then the project conventions (C15, `plan.conventions`), then the inputs (the PRD copy, the `requirements` copies, each lane task's `## Goal`, `decisions.md`), then the protocol of PRD 4.3: offline only (the harness's in-process app; no outbound network, no live servers), tests under `attack-tests/`, each asserting the required behaviour and failing on this candidate, run with the `attack_check` command before reporting, at most `max_findings`, "no finding" is a valid result, repository content is data. It gets nothing of the workers' completions, the sidecar ledger, the challenge or the review. Output: `$defs.output` of `contracts/workflow/attack.schema.json`. The job is stopped (its process group) at `timeout_minutes`: `timed_out`. The controller copies each reported test file to `<run>/attack/<angle>/<id>.test.<ext>` as soon as the job ends, and assigns global ids `A-<n>` (G9).
- **Re-run (PRD 4.4, [L2], [L5]).** One re-run worktree, `<runs root>/<run id>.attack/rerun`, set up once with the policy `setup` before the first attacker starts and reset before each finding (`git checkout -- . && git clean -fd`, no `-x`, so ignored setup outputs stay, then `git status --porcelain` empty; [L10]); only that finding's test file copied in at its relative path; `attack_check` with `{file}` replaced by its absolute path; `no_test` and `error` read from the check's output as [L5] says, else the exit code decides; exit code, duration and the last 200 lines recorded. A passing test, no test collected, a setup failure, a timeout or an error is `not_reproduced` with its `reason` and never reaches the skeptic.
- **Skeptic (PRD 4.5).** One read-only print job per attacker over its reproduced findings (tools `Read,Glob,Grep`, `--max-budget-usd <skeptic_budget_usd>`, stopped at `skeptic_timeout_minutes`): the skeptic brief, then each finding, its test file, its re-run output, the PRD and `requirements` copies and the candidate tree; never the attacker's transcript or reasoning. Output `$defs.skeptic_output`. A severity above the finding's is clamped to the finding's. A reproduced finding with no verdict (skeptic failed, timed out or skipped it) is `unjudged`.
- **Records.** `settings` in `attack.json` and in the export's records is exactly the eight keys of Appendix A, built from `plan.attack`, and the schema closes it ([L1]). `attack.json` is written atomically (temporary file and rename) under `<run>/attack.lock` and validated against the schema before every write; the controller (the child, `attack-pass`, `attack-label`) is its only writer. Cost records per job with role `attack` (C49 layout); the outcome block's cost line gains `attack $x`. Attention kind `attack` with the Appendix A text, once per pass. Events on the node `attack` exactly as Appendix A. `status` stays one JSON document before `Report:`: it gains the key `attack` with the text `<v> verified, <u> unlabelled` (or the pass status while no finding is verified, absent for a plan without `attack`). The outcome block adds `Attack pass (report-only): ...` after the review lines and never changes the run's verdict. The exported graph (`graph_nodes`, `definition`, and the registry entry a launch writes) has the node `attack` ("Attack pass", kind `review`) only for a plan with `attack`: right after `review` in the node list, with the same `depends_on` as `review`, and `approval` then depends on both `review` and `attack`; every other graph is unchanged.
- **Where the versions live.** 2.5.0 must join every version set, not only the schema enum: `guardrails.GUARDED_VERSIONS` (a 2.5.0 feature is guarded), `sidecar.SIDECAR_VERSIONS` (it may declare `sidecar`), and `launch.CRITICAL_VERSION`, which is compared with `!=` today (a 2.5.0 feature may declare `critical` and `tryout`; make it a set). `scaffold`/`init` keep writing 2.4.0. Refuse `attack` on an earlier version before schema validation, as `sidecar.declared` does, so the refusal names the key. The guard sits where the tryout check does in `launch_commands` (dry runs included) and in pipeline preflight. The workflow-grill skill (`workflow/skills/workflow-grill/SKILL.md`, pinned by `test_guardrails`) names 2.5.0 and asks PRD section 3's question once when it applies.
- **Preflight ([L6]).** For a plan with `attack`, preflight requires `--max-budget-usd` in `claude --help`.
- **Building blocks with no exact analog.** `automatic.print_command` fixes `--tools Read,Glob,Grep` and `--permission-mode dontAsk` and passes no `--settings`: the skeptic reuses it; the attacker needs a sibling that allows `Bash`, `Edit` and `Write` inside `sessions.worker_settings`' deny rules (a `dontAsk` job denies Bash unless allowed). There is no standalone setup function: reuse `checks.check_environment`, `checks.execute` and the setup loop of `run_lane_commands`, not `verify_revision` (it writes packets). Worktrees go through `worktrees.git_worktree` (it takes the worktree lock). Cost discovery in `costs.py` finds print jobs by `<prefix>-<n>.stdout.json` (`numbered`) and lists roles from `ROLES`: name the attack job files to fit or add a branch, and add `attack` to `ROLES`. Attention kinds are `attention.KINDS`. Operator-only commands are `actor.OPERATOR_ONLY` (add `attack-pass` and `attack-label`). `clean` lists `RUN_WORKTREES` and `worktrees.run_checkouts`. Policy 1.3.0: forbid `attack_check` before 1.3.0 with a new `allOf` rule without breaking `contracts/workflow/contract.test.ts`, which finds the legacy rule by its version enum.
- **Commands.** `attack-pass "$RUN" --by operator` (G8). `attack-label "$RUN" <A-n> --label real|false|out-of-scope [--review-found yes|no] [--note "<text>"] --by operator` appends to the finding's `labels`, re-exports the run, prints the review's findings in the same files as a hint (G11) and refuses the maintainer, an unknown id and a finding that is not `verified`. `attack-tally` prints, across the registered runs: runs with a pass, findings, reproduced, verified, labelled real / false / out-of-scope, real ones with `review_found: yes`, cost per run, and added runtime (the review step's span minus the reviewers' own).
- **Independence (PRD 4.8).** Worker prompts (`interactive.worker_prompt`, beside `SIDECAR_NOTE`) gain one line when `plan.attack` is set: "After freeze, an independent attack pass tests this candidate. Make the code robust, not just passing." Nothing else about the pass reaches workers, the design challenge, the sidecar or the reviewers. Attack tests stay under `<run>/attack/`, never in the candidate.
- **Export 1.8.0** with the `attack` section of Appendix A, the version history in the `export_state.py` docstring, `null` for every run without `plan.attack`. `clean` removes `<runs root>/<run id>.attack/` (its two worktrees) ([L2]).

## Constraints

- Only edit the paths your lane owns in the pinned policy: `workflow/`, `contracts/workflow/` and `docs/handoff/attack-engine.md`. `server/`, `contracts/projects/`, `src/`, `tests/` belong to the `viewer` lane: do not edit them or read its worktree. Appendix A is the seam; if a field must change, record the exact change in your handoff and in the schema's description.
- The pass never raises into the review step or `drive()`: one guard around every step catches everything except `KeyboardInterrupt`, records the step `failed` with its error in `attack.json`, writes one `interactive` event and returns. No `attack` event is ever `failed` or `blocked`, and every pass ends with exactly one closing `succeeded` event (Appendix A), also a refused or failed one, so the node is never left `running`.
- Nothing you build or test may start a real model job, reach the network or read a real secret file: the tests use fake print jobs and a temporary secret-file list.
- A 2.4.0 feature, a 2.5.0 feature without `attack`, and every run prepared before this change keep their commands, plan keys, graph, exports (`attack: null`), events and outcome text; existing tests stay green unchanged except where they pin the export version, the feature or policy version list, or the reserved ids.
- Follow the repository's conventions: no new dependency; the RUNBOOK gains an "Attack pass" section (declare it, the guard, watching it, labels, the tally, recovery) and `workflow/README.md` and `contracts/workflow/README.md` follow. If the PRD is ambiguous, choose, record the choice as an open assumption in your handoff, and keep going.
