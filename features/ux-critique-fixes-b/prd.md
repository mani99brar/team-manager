## 3. Goals

1. Every run list (Triage, the project page, the feature page) can be filtered by status, stopped-at phase, date and text, and sorted; each says which runs it searched.
2. Runs that need the operator, then running runs, are on top by default everywhere, under a sub-header that names the order, with a chronological alternative.
3. The project page's first screen shows its features as one row each, with state and date; every run row carries its date and duration.
4. A list's search, filters, sort, grouping and expansion survive opening a run and pressing Back, and survive a reload.
5. The run page's first screen reads its steps at the standard level or closer, says how long ago a finished or stopped run stopped, announces the sessions below, opens the page its "Open" link names, and shows branch and base instead of the definition hash.
