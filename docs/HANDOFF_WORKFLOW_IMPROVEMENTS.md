### Slice 1: keep every verdict, an honest record (P1, P2, P3, Q1, Q2; merged at 0b064e6)

- **C33, every reviewer's verdict is kept.** A block no longer decides alone.
  - Native reviewers: the first accepted block starts a 10-minute grace (`REVIEW_GRACE_SECONDS` = 600) from its `accepted_at`. A resumed controller continues the same window. Other reviewers' files are read at each poll and recorded as late verdicts (`late: true`). A late verdict can add a blocker. It never makes the review approved.
  - Print reviewers (every pine run): each job is read as it exits, not in declared order. After a block, running jobs finish within their own deadline. This is the case that dropped finished security P0/P1s in 5 pine runs.
  - One `blocked` event names each blocker with its open P0/P1 counts, and the reviewers without a verdict. The error quotes the first sentence of up to three open P0/P1s. A reviewer session lost during the grace is only noted, and `review.json` keeps the block. A missing, a worker's or a shared reviewer session id still refuses the record.
- **C40, one review record.** `review.json` is the record, and `automatic-review*.json` is restart state. The unread `decision` key is gone. Both transports write `accepted_decision`. The review worktree check uses `git status --porcelain --ignored`, so configuration planted under an ignore rule refuses the verdict.
- **C18, finished turns behind a stale row.** A turn is over when the row's state is idle or done, or its status is idle. While a question waits, only a busy row (status busy, or state working with no status) counts as a pane answer. A completion that waits over 2 minutes for its turn to end gets one event naming the raw state and status. No stable-hash acceptance.
- **C34 stage 1, derived verdicts and one rubric.**
  - The controller derives each reviewer's verdict from its findings. An unresolved P0/P1 blocks, and so does `blocked` with no findings. Anything else is approved. `review.json`'s `reviewers[].verdict` is now the controller's verdict. The reviewer's own word stays in its status file as `accepted_decision`, and one note names each override.
  - `REVIEW_RUBRIC` follows every brief in both transports. Coverage (`workflow/prompts/reviewers/coverage.md` and the feature copies) blocks only on four cases: a shown failure, a contradicted quoted line, a disclosed failure, a line it could not check because its test source or packet was unreadable. 1.1.0 workers end their summary with a Proof table.
  - Not built: stage 2 (a `relation` field, reviewCompletion 1.3.0). The replay follow-up (V1) is under slice 2.
- **C35, worker claims to reviewers.** Every reviewer of a 1.1.0 run reads each lane's `open_assumptions`, `untested`, `falsifying_check` and `verify_yourself` inline, marked unverified. The prompt names the PRD copy and `policy.json`. Each lane's block is cut at 4000 characters. An unreadable completion adds one line and never fails the review. Reviewers still never get the sidecar ledger or the challenge notes.
- **C11, challenge reruns.** A bare `resume` on a paused challenge with unchanged pinned files exits 1 and writes nothing. The refusal names the ways on: edit the task files, `decisions.md` or the PRD; record `--accept-challenge "<reason>"`; or start a new run. From attempt 2 the prompt lists the earlier P0/P1s and the changed files. No attempt cap. When edits wait, `status` and the override run resume's read-only checks first, and say `resume refuses: <reason>` if resume would refuse.
- **C16 steps 6 and 7.** The worker prompt states the lane's deadline in UTC. A typed answer ends with `[Controller: your deadline is now <UTC time> (UTC); ...]`. The Stop line now holds only the authored `## Stop` text, not the approved checks after it.
- **C24 steps 1 and 2.** Freeze reads `diff-tree -z`, so a non-ASCII or quoted file name no longer blocks freeze. `validate_bundle` requires the run's base and one worker and one candidate packet per lane. The verification cache refuses a packet of another phase, node or attempt. Step 3 (a preflight refusal) is deferred.
- **C44, an honest record and the attention record.**
  - New `workflow/attention.py` writes `<run>/attention.json` (one record per open state). It appends one line per new state to `attention.jsonl` beside the Projects registry (`~/.config/md-manager/` here). It never raises. Kinds: question, pane, challenge_paused, review_blocked, controller_blocked, finished, then sidecar (slice 2) and awaiting_approval (slice 3). usage_limit stays reserved for C46.
  - New events: `Controller blocked: the <step> step failed: <error>` before drive's non-retryable raise; the candidate gate's reasons as a second event (`Combined revision <sha>` unchanged); deferred checks with exit codes (`recorded for the candidate gate: build (exit 1)`); `passed on attempt N after attempt N-1 failed`. A changed source branch or an unfinished start is an `interrupted` row naming the step that continues the run. The viewer offers that step.
  - `status` takes no lock, writes nothing and prints the next step from the finish policy. `export` now rewrites `report.html`. The challenge prints `Design challenge attempt <n> still running (<m> min)` each minute, and Ctrl-C prints the `resume` command.
- **C51 step 2, the record matches what will happen.** Packets no longer carry `pending_gates`. `integration_approval` is documented as a schema constant and is not refused. launch's first line says how the run ends.
- **C39, review replay.** `python -m workflow.replay` reruns a past run's reviewer with this checkout's prompt on a scratch copy that holds no recorded verdict. It writes `tally.json`: raw and derived verdicts, findings, cost and duration. At most two jobs run at once, and none under 1.5 GB of free memory. Narrower than the audit: no adaptive sampling, every reviewer runs through the print transport, and labels are written by hand.
