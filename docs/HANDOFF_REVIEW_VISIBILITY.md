# Handoff: review visibility and run inputs (PRD_REVIEW_VISIBILITY, slices A, B, C)

Implements `docs/PRD_REVIEW_VISIBILITY.md` and its three slice PRDs on branch `ultra` (worktree `~/dev/md-manager-ultra`), 2026-09-21. All three slices were implemented directly in this checkout rather than as feature runs; the feature directories `features/review-result/` and `features/run-inputs/` and the `launch` choices the PRDs ask for exist, so the runs can still be launched, but nothing in the tree depends on them. Commits are left to the user. Section 6 lists what was deliberately not done.

## 1. What changed, by slice

### Slice A: reviewer as an attachable native session (`workflow/`, `contracts/workflow/`)

- `contracts/workflow/reviewCompletion.schema.json`: the reviewer's completion file (`version`, `run_id`, `node_id: "review"`, `launch_token`, `bundle_sha256`, `candidate_commit`, `verdict`, `findings[]` with `severity`, `message`, `disposition`, `worker` (`ui|adapter|both|none`) and `requirement` (verbatim quote or null)).
- `workflow/interactive.py`: `InteractiveSessions` knows the reviewer as node `review` (`launch_name` `workflow-<run>-reviewer`, `node_worktree` = `<run>/review-worktree`, `locate`/`settle` reused); `run_reviewer()` launches `claude --bg` with tools Read, Glob, Grep, Write, permission mode `dontAsk`, `--allowedTools Edit(//<run>/review.completion.json)`, `--add-dir <run>`, writes `review.interactive.json`, `review.prompt.txt`, `review.launch.log`; workers now also get `<worker>.prompt.txt`. `attach_panels` adds a third pane when the reviewer exists; `attach_reviewer_panel` adds it to an existing tab (split right of the adapter pane, label `Claude: reviewer`); `attach-one --node review`.
- `workflow/automatic.py`: `reviewer_transport` setting (`native` default, `print` fallback; plans pinned before the setting validate as native); `review_candidate` dispatches to `_review_native` (launch, `wait_review`, `read_review_completion` with schema validation and run/token/bundle/candidate binding, identity/independence/worktree/evidence re-checks, `review.json` for every verdict, identity-checked stop) or `_review_print` (the previous headless job, now also recording `worker`/`requirement`). Resume: a receipt at `running` re-enters `wait_review`; `KeyboardInterrupt` leaves the reviewer running. A native session in state `blocked` (needs a human in its pane) keeps the wait going until the deadline; no second reviewer is ever launched.
- `workflow/pipeline.py`: `launch_reviewer` (events with the reviewer UUID, best-effort pane), `stop_session`/`stop_reviewer` (generalised from `stop_workers`), `check_review`/`blocking_findings` (findings may carry `worker`/`requirement`; `require_approved=False` for export), `--reviewer-transport` at `prepare`, `ExportRuntime`/`export_run` and the `export` CLI action.
- `workflow/launch.py`: features `project-workflows`, `review-result`, `run-inputs`; `--reviewer-transport`; `--run-id` defaults to `<feature>-001`.
- Docs: `workflow/RUNBOOK.md` ("Automatic mode: the review step", resume path for the reviewer transcript, `workflow export`), `features/project-workflows/README.md` (new files, export 1.2.0 seam), `workflow/README.md`, `contracts/workflow/README.md`.

### Slice B: review verdict and findings in the viewer (`contracts/projects/`, `workflow/export_state.py`, `server/`, `src/projects/`)

- Contract 1.1.0/1.2.0: `reviewResult` (`.../runs/{run}/reviews/{attempt}`) in `contracts/projects/v1.ts` with `validateReviewResult`/`isBlockingFinding`, generated `reviewResult.schema.json`, fixtures and negative tests in `examples.ts`/`contract.test.ts`, README "Versions" section.
- Export 1.2.0 (`workflow/export_state.py`): `review` section from `review.json` plus the reviewer receipt (transport, session, `reviewed_at`, `review.diff` hash and size); `workflow export <run>` rebuilds `run-state.json` for old runs.
- Adapter (`server/projects.ts`, `server/projectRoutes.ts`): accepts export versions 1.0.0/1.1.0/1.2.0, projects the section (redaction, diff registered as artifact `patch-review-<sha12>` with hash and size checks), review node gets `session_id`/`result_uri`; 404 `REVIEW_NOT_FOUND` for runs without the section; strict section validation (`RUN_STORAGE_INVALID`, never a path).
- UI: review panel on the review node (verdict pill, reviewer session and transport, bundle hash linked to the candidate node, summary line, findings grouped by disposition, "Diff the reviewer saw"), "no review recorded" for legacy runs; mocks (worker phase) and seeds (candidate phase); scenarios `review-verdict`, `review-blocked`, `review-legacy`, `paths-redacted`.

### Slice C: run inputs and finding-to-task links

- Contract 1.2.0: `runInputs` (`.../runs/{run}/inputs`) and `requirement_found_in` on review findings (the lanes whose task text contains the quote verbatim; the adapter never guesses).
- Export: `inputs` section from `plan.json`, `policy.json`, launch receipts, completion signals, handoffs, stop files and the recorded prompts.
- Adapter: `.../inputs` route, redaction, 64 KiB truncation with a marker, timestamps normalised to `Z`, `INPUTS_NOT_FOUND` for runs without the section, verbatim quote lookup against the raw task text.
- UI: Assignment tab and run-header facts, worker node panels (Task with Rendered/Source toggle and highlight, Exact prompt, Launch receipt, Reported by the worker, Handoff as accepted, Stop confirmation), finding quotes linking to the worker's task scrolled to the highlighted quote; scenarios `run-assignment`, `worker-inputs`, `finding-to-task`, `inputs-legacy`, `inputs-paths-redacted`.

## 2. How it was built and audited

The contract (`contracts/projects/v1.ts` 1.2.0, `contracts/workflow/reviewCompletion.schema.json`) and a design spec pinning the export format were written first; three workstreams (controller, adapter, UI) were then implemented in parallel against them, each red-first, and merged. After the merged tree was green, an adversarial audit ran six independent read-only lenses over the uncommitted diff against the PRDs (controller protocol, adapter security, export-shape consistency, PRD completeness, UI and browser tests, Python test honesty); the lenses reproduced their claims with scratch probes and mutation runs. Every finding was verified by hand and fixed (section 6 lists the behavioural ones): redaction gaps next to Markdown punctuation and `file://` URIs, a finding link that could point past the served text's truncation, a check-ID rule that would have hidden a whole workflow behind one `test:unit` policy, an invented reviewer transport for pre-slice-A plans, an interrupted native review projecting as pending, a false RUNBOOK claim about `attach`, a Ctrl-C in the reviewer launch window that stranded the session, a post-acceptance stop that was never retried, the unlinked diff `uri`, a vacuous browser assertion, an unrecorded deviation on findings grouping, and five untested guards (identity, independence, worktree and evidence re-checks, print-mode `worker`/`requirement`, best-effort pane, launch-failure receipt). Guard removals were confirmed to fail their new tests on scratch copies. The live smoke tests in section 4 found the two launch-time defects (variadic option order, permission-rule family) that neither the offline tests nor the audit could see.

## 4. Red/green notes

- Contract: the new schemas were written first with positive and negative fixtures; `npm run contracts:export` regenerated the JSON schemas; 13/13.
- Adapter: eight tests failed for the expected reasons against the old adapter (a 1.2.0 export was `RUN_STORAGE_INVALID`, the new routes were `NOT_FOUND`), then 28/28; two audit-driven tests (redaction spellings, served-text links, policy-label IDs, null transport; interrupted review projects as paused) brought it to 30/30.
- Controller: the workstream reported behavioural reds per increment (fake reviewer through `FakeSessions`, four-process reviewer-interrupt recovery, every rejected completion file, print fallback), then 108/108; the audit fixes added 15 tests (launch-window interrupts, stop retry, identity/independence/worktree/evidence refusals, print-mode finding fields, best-effort pane, launch failure, `attach` reviewer pane, recorded transport) and one prompt test, 124/124, with guard removals confirmed red on scratch copies.
- UI: the nine new scenarios failed first for behavioural reasons (no tablist, no task panel, no findings rows, no not-recorded sentences) with the six existing ones passing, then 15/15 in both phases; the audit fixes (group-by toggle, pinned receipt assertions, diff link by ID) kept both phases at 15/15.
- Live smoke test (slice A section 5), scratch run built from a copy of project-workflows-001's bundle, diff and packets with the review node driven on its own:
  - Attempt 1 failed in seven seconds and found a defect the offline tests could not: `--add-dir` is variadic, so the prompt that followed it was swallowed and the session started idle ("send a prompt to start"); the controller then saw the session's `blocked` state and stopped it. Fix: the prompt now follows `--permission-mode dontAsk` (single-valued) and a test pins that order; `wait_review` now treats `blocked` as "needs a human in the pane" and keeps waiting until the deadline instead of failing.
  - Attempt 2 (session a4c348e5, launched 20:07:35Z, pane `Claude: reviewer` attached in tab w5:tG): the prompt arrived and the reviewer read the diff, packets, contracts and screenshots, but its single `Write` of the completion file was denied: under `--permission-mode dontAsk` a rule spelled `Write(//path)` never matches. The reviewer stopped correctly rather than working around it and put its full verdict (approved, nine P2 findings) in the transcript. The controller kept waiting through the session's `done` state and, at the 20-minute deadline (1205 s), reported "Reviewer deadline exhausted; no second reviewer is launched", stopped the session with the identity re-check (`review.stop.json`), marked `automatic-review.json` `blocked` and wrote no `review.json`: the deadline path, live.
  - A print-mode experiment (`/tmp/permtest`, four variants) established that file writes are governed by the `Edit` rule family: `--permission-mode dontAsk --allowedTools "Edit(//abs/path)"` writes exactly that file and denies every other path, `Write(//abs/path)` matches nothing, and `acceptEdits` allows every write. The launch now uses `Edit(//<run>/review.completion.json)`; the test pins the spelling.
  - Attempt 3 (session 25d99bf4, 741 s): the prompt arrived, the pane attached, and the single allowed write succeeded: `review.completion.json` was written with the right run, token, bundle hash and candidate (verdict approved, eight findings with `worker` and `requirement`). The controller rejected it as a whole, fail-closed, because the reviewer had invented severity `P3` ("Review completion signal violates the schema: 'P3' is not one of ['P0', 'P1', 'P2']"), marked the receipt blocked, stopped the session with the identity re-check and wrote no `review.json`. The prompt only showed one example finding; it now spells out every allowed value (severities, dispositions, workers, verdicts, no other keys), pinned by a test.
  - Attempt 4 (session f36b923d, 615 s): the accept path, live. The reviewer wrote a valid `review.completion.json` (approved, eight P2 findings, each with `worker` and a `requirement` quote), the controller accepted it once the session was idle, re-checked identity, independence, worktree, bundle and diff hashes, wrote `review.json`, marked `automatic-review.json` `succeeded` with `accepted_at`, stopped the session with the identity re-check (`review.stop.json`, `stopped: true`) and left the transcript resumable (`cd <run>/review-worktree && claude --resume f36b923d-…`). `claude agents --json` listed the reviewer under `workflow-project-workflows-001-reviewer` with a UUID distinct from both workers, and a `Claude: reviewer` pane existed in the run's tab for every attempt. The export's `review` section of the scratch run derives `transport: native`, the session UUID, `reviewed_at`, the diff hash and the linked findings.
  - Verbatim match rate of the live reviewer's requirement quotes (PRD_RUN_INPUTS open question): 8 of 8 quotes were found verbatim in the named worker's task text, so no fuzzy matching is needed.
  - The reviewer's eight findings concern the already-merged candidate b5385b3 (the Projects viewer feature), not this change set; they are retained in the scratch run's `review.json` for the operator: event normalisation only emitting status/log events, phase-conditional assertions in the run-evidence scenario, thin regression coverage of the Pi/Claude experience, per-request packet loading in `listRuns`, one malformed run directory making a whole workflow unbrowsable, inconsistent redaction in `projectWorkerResult`, the app-wide `frameworkErrors` handler, and event-derived attempt numbers. Several restate the print-mode reviewer's earlier findings.

## 6. Decisions, deviations and limits

- Contract versioning: the four existing payloads keep `contract_version: "1.0.0"`; `reviewResult` and `runInputs` carry `"1.2.0"` (reviewResult was introduced at 1.1.0 and gained `requirement_found_in` in 1.2.0; both shipped together here).
- Reviewer tools: Read, Glob, Grep plus Write of exactly one path (the completion file); the PRD's "Read, Glob, Grep only" cannot produce a file, so the single allowed write is the minimal deviation and is documented in the RUNBOOK.
- An `approved` verdict carrying an unresolved P0/P1 is recorded as `verdict: "blocked"` in `review.json` (the reviewer's raw decision is kept in `automatic-review.json`), so every persisted review satisfies the contract's cross-field rule.
- Stop after acceptance: the receipt is marked `succeeded` before the reviewer is stopped; if that stop fails the review node records the error and the operator stops the reviewer by its exact ID (RUNBOOK).
- Task display: both the pinned task (rendered Markdown with a Source toggle) and, when recorded, the exact prompt; three-pane layout: same tab. Both recorded in the umbrella PRD's decisions log.
- Completion-file binding: the file binds a controller-issued `launch_token` (a UUID put into the reviewer prompt) rather than the reviewer session UUID the PRD table names, because the native session's UUID does not exist when the prompt is composed; the session identity is enforced out of band at acceptance from `review.interactive.json` against `claude agents --json` (must equal the launched session and differ from both worker UUIDs). Recorded in the PRD table and the umbrella decisions log.
- Findings grouping: the review panel groups by disposition (open, resolved, accepted) with a Worker column and offers a "Group by: Worker" toggle (ui, adapter, both, none, not recorded), which is how PRD_RUN_INPUTS' "findings grouped by worker" is met alongside PRD_REVIEW_RESULT's grouping by disposition.
- `automatic.reviewer_transport` is nullable: the export records the transport the plan pinned, or the one a recorded review actually used, and null for a run pinned before the setting that never reviewed; it never defaults to `native` (an audit found the earlier default contradicted `review.transport` for project-workflows-001).
- Check and scenario IDs in `runInputs` are free-form policy labels (the policy schema allows any non-empty string, e.g. `test:unit`); an earlier draft required the route-ID pattern and would have hidden a whole workflow behind one such run.
- Audit-driven fixes after the first green run: redaction now covers paths adjacent to Markdown punctuation and `file://` URIs; a quote links only when it also survives in the served (truncated) task text; the viewer builds the diff link from the artifact ID like every other artifact; an interrupted native review projects as `paused` rather than `pending`; `attach` adds the reviewer pane to an existing tab; a Ctrl-C in the reviewer's launch window is resumable; the post-acceptance stop is retried on resume; the identity/worktree/evidence re-checks, print-mode `worker`/`requirement` recording, the best-effort pane and the launch-failure receipt are now covered by tests.
- Not done: no fuzzy requirement matching (verbatim only); no live streaming; no viewer controls; the feature runs `review-result`/`run-inputs` were not launched.
